## 2. Démarrer et arrêter le SI

Prérequis : VirtualBox, Vagrant, ~4 Go de RAM, dossier du projet.

```powershell
cd D:\lab-bloc5\TP-Mrdecker\Wokrshop-final
vagrant status
vagrant up
```

Attendu : `web-prod`, `fw-router`, `supervision` en `running`.  
Le premier `vagrant up` télécharge les binaires (long). Les suivants réutilisent les disques.

| Action | Commande |
| --- | --- |
| Arrêt propre | `vagrant halt` |
| Reprise | `vagrant up` |
| Rejouer Ansible | `vagrant provision` |
| SSH | `vagrant ssh web-prod` (idem `fw-router`, `supervision`) |
| Destruction | `vagrant destroy -f` (reconstruire ensuite avec `vagrant up`) |

Ne pas lancer `ansible-playbook` sur l'hôte Windows. Chaque VM s'auto-provisionne (`ansible_local`).

## 3. Guide SRE — usage quotidien

### 3.1 Tableau de bord unifié

1. Ouvrir `https://127.0.0.1:3443` (accepter le certificat).
2. Menu **Dashboards** → dossier **M2-Shop** → **M2-Shop - Observabilité Unifiée (Production)**.
3. Plage : **Last 1 hour**, rafraîchissement 10 s.

| Panneau | Lecture |
| --- | --- |
| Requêtes / s | Trafic Nginx (Loki) |
| Taux 4xx / 5xx | Erreurs HTTP |
| CPU / mémoire | Node Exporter (`10.0.20.20:9100`) |
| Logs bruts | `access.log` + `error.log` |

### 3.2 Explorer un log (Loki)

1. Menu **Explore** → datasource **Loki**.
2. Mode Code, exemples :

```
{job="nginx_access"}
{job="nginx_error"}
```

3. Plage **Last 1 hour**, **Run query**.

Les heures dans le texte des logs sont en **UTC** (horloge VM). Grafana affiche l'heure du navigateur (ex. Paris UTC+2).

### 3.3 Vérifier que la collecte vit (sans casser le site)

```powershell
vagrant ssh web-prod -c "curl -k -s -o /dev/null -w '%{http_code}' https://localhost:9100/metrics"
vagrant ssh supervision -c "curl -s http://localhost:9090/api/v1/targets"
```

Attendu : **401** (Node Exporter sans mot de passe) ; Prometheus `"health":"up"`.

### 3.4 Ce qu'il ne faut pas faire

| Action | Pourquoi c'est faux |
| --- | --- |
| `curl https://10.0.20.20/` depuis supervision | Port 443 Admin→Prod **interdit** en FORWARD (timeout) |
| SSH de web-prod vers supervision (port 22) | DROP Zero-Trust — c'est un test, pas un outil d'admin |
| `scp` des logs vers 10.0.10.5 | Port 22 inter-zones interdit ; utiliser `/vagrant` |
| Compter sur le hostname `fw-router` | Noms internes : `fw-router-prod` / `fw-router-admin` |

L'admin SSH se fait **depuis l'hôte** : `vagrant ssh …` (NAT `eth0`).

### 3.5 Alertes

- Canal Slack du labo : **`#alertes-m2shop`** (pas `#monitoring`).
- Alerte métier : **NginxDown** — le service `nginx.service` n'est plus actif.
- L'auto-healing relance Nginx via le compte `healer` (une seule commande sudo).
- Pour silencer pendant une intervention **depuis supervision** :

```powershell
vagrant ssh supervision -c "amtool --alertmanager.url=http://127.0.0.1:9093 silence add alertname=NginxDown --comment='Maintenance' --duration=1h"
```

Alertmanager n'écoute pas 9093 depuis l'extérieur.

## 4. Guide administrateur — incident et reconstruction

### 4.1 Isolation d'urgence (rappel)

Procédure complète : DAE, section 3. En quatre phrases :

1. Confirmer via Grafana / Slack / Prometheus — **pas** via un curl 443 depuis l'Admin.
2. Sur `fw-router` (`vagrant ssh fw-router`) : DROP FORWARD `saddr`/`daddr` 10.0.20.20.
3. Preuves vers **`/vagrant`** (tcpdump, tar des logs), jamais en SCP vers supervision.
4. Silence Alertmanager en local sur supervision.

### 4.2 Relancer uniquement le site (sans isolation)

Si Nginx est arrêté et que l'auto-healing n'a pas encore tourné (ou pour un test) :

```powershell
vagrant ssh web-prod -c "sudo systemctl start nginx"
```

Le compte `healer` ne peut **que** `systemctl restart nginx.service`. Tout le reste exige un compte sudo SRE.

### 4.3 Reconstruire une VM

```powershell
vagrant destroy web-prod -f
vagrant up web-prod
```

Puis rejouer les tests A–D concernés (`docs/tests-de-validation.md`) avant de remettre le service dans la boucle de supervision. Sur fw-router, retirer d'éventuelles règles d'isolation `nft insert` avant de reconsidérer le FORWARD.

### 4.4 Sauvegarde (ce que le SRE ne doit pas attendre)

Il n'y a **pas** de job de backup. Détruire `supervision`, c'est perdre l'historique Zabbix/Loki/Grafana. On **reconstruit** (`vagrant up`) ; on ne **restaure** pas. Les seuls fichiers à conserver hors VM sont le dépôt Git et, en incident, les archives `/vagrant` (PCO). Voir DAE § 3.2.

## 5. Guide « utilisateur boutique » (synthèse)

Le client final n'a **aucun** compte sur ce SI.

1. Accéder au site en HTTPS (redirection automatique depuis HTTP).
2. En cas de page d'erreur temporaire : l'auto-healing vise un rétablissement < 60 s ; ne pas « relancer le serveur » côté client.
3. Toute anomalie de contenu ou de paiement sort du périmètre de ce PoC (pas de tunnel vers la DMZ Admin).
